PROJECT RE:STEP — 実行計画書

STEPNコンティンジェンシー計画
「Xデー」に備える5チーム体制

FSLによる開発停滞・サービス停止リスクに備え、コミュニティ主導で現行STEPNと同等の体験を提供する後継アプリを開発するための組織編成と実行計画。

作成日 2026年7月3日 体制 5チーム編成 計画期間 Phase 0〜3(約18ヶ月)
背景と課題認識02

なぜ今、コンティンジェンシー計画が必要か

現状STEPN / FSLの状況

  • 新機能開発が実質ストップし、アップデートが停滞
  • コミュニティが求める改善(GSTユースケース追加、ジェム管理画面、シューズ管理・閲覧UI、ランキング機能など)が放置されている
  • 運営(FSL)の経営状態・継続意思がユーザーから見えない

リスク想定される「Xデー」シナリオ

  • シナリオA:開発中止の正式アナウンス(サービスは当面継続)
  • シナリオB:FSLの倒産・組織解体によるサービス即時停止
  • シナリオC:段階的縮小(サーバー維持のみ、マーケットプレイス閉鎖)
基本方針:Xデーが「来てから」動くのでは遅い。リサーチ・開発・法務を並行で走らせ、どのシナリオでも数週間以内に代替アプリへ移行案内できる状態を作っておく。
目的とゴール03

本計画の3つのゴール

GOAL 1体験の継続

現行STEPNと同等の操作感(スタート→計測→リザルト)を持つ代替アプリを用意し、ユーザーの「歩いて稼ぐ習慣」を途切れさせない。

GOAL 2エコシステムの改善

本家で放置されてきた課題(GSTユースケース不足、マーケットプレイスの構造問題、チート対策)を分析し、後継アプリでは設計段階から解決する。

GOAL 3合法かつ持続可能な運営

日本法・豪州法の規制を精査し、トークン設計・運営体制を「グレーではなく白」で構築する。継続可能な収益モデルを持つ。

重要な前提:本家のNFTシューズ・GST/GMT残高は、FSLの協力なしに新アプリへ「移行」することは技術的にできない。本計画はあくまで「独立した後継アプリ」であり、本家資産の救済を約束するものではない——この点はコミュニティに最初から誠実に伝える。

組織編成05

5チーム体制の全体像

① 管理チーム(PMO)全体統制・意思決定・セキュリティ・予算
② リサーチチーム現行仕様・市場・脆弱性の分析と問題提起
③ アプリ開発チーム後継アプリの設計・実装
④ アプリサポートチームテスト・デバッグ・QA・不具合管理
⑤ 法務チーム規制調査・IP・拠点移転の論点整理

統制の原則

  • 意思決定は管理チームに一元化(各チームは提案権を持つ)
  • チーム間の情報は共有リポジトリ+週次同期会で全チームに開示
  • 法務チームは拒否権を持つ(規制違反リスクのある機能はリリース不可)

チーム詳細 ②06

リサーチチーム — 分析・解析・問題提起

ミッション

現行STEPNの仕様・経済圏を定量的に解剖し、「何を引き継ぎ、何を直すか」の判断材料を全チームに供給する。

主な調査領域

  • GST/GMTの発行・バーン構造とインフレ耐性の検証
  • マーケットプレイスの問題点(手数料、流動性、フロア価格操作、ボット)
  • エコシステムの脆弱性(GPS偽装・チート手法の傾向、新規参入者の損益分岐)
  • アクティブユーザーの要望調査(ランキング、ジェム管理UI等の優先度)

成果物

現行仕様書(リバースエンジニアリング版)

開発チームがそのまま実装に使える粒度のエナジー・報酬計算仕様

トークンエコノミー分析レポート

GST崩壊の要因分析と、後継アプリでの経済設計への提言

マーケットプレイス改善提案書

問題提起+新設計案。管理チーム経由で開発チームへ

週次ウォッチレポート

FSLの動向監視(Xデー予兆の早期検知)——管理チームへ直送

チーム詳細 ④08

アプリサポートチーム — テスト・デバッグ・QA

ミッション

開発チームの成果物を実環境で検証し、エラー・動作不具合を再現手順つきで報告・追跡する。品質ゲートの番人。

活動内容

  • 実機・実地テスト(徒歩/ラン/自転車誤検知、都市部・トンネル等のGPS精度)
  • 報酬計算の検算(リサーチチームの仕様書と実装の突合)
  • チート耐性テスト(位置偽装アプリ・エミュレータでの侵入試験)
  • 不具合トリアージとリグレッションテストの自動化

品質ゲート(リリース基準)

  • クラッシュフリー率 99.5%以上
  • 報酬計算の誤差 0件(金銭に関わるバグは重大度最高)
  • 既知のGPS偽装手法での報酬取得が遮断されていること
  • 優先度「高」の未解決バグ 0件
成果物: テスト計画書、バグトラッカー運用、リリース判定レポート(管理チームへ提出)
チーム詳細 ⑤09

法務チーム — 規制・IP・拠点移転

最重要論点トークンと日本法

  • 取引所で売買可能なトークンの発行は、日本では資金決済法上の暗号資産に該当し得る(交換業登録・JVCEA審査等の高いハードル)
  • ステーキングや配当性があれば金融商品取引法の論点も発生
  • → だからこそ初期MVPはトークンなし(ポイント制)で開始し、トークン化の可否・スキーム(海外発行体、IEO等)を並行調査する

要注意知的財産リスク

  • 「STEPN」名称・ロゴは商標——後継アプリは別名称で展開
  • UIデザイン・アートの複製は著作権侵害リスク——「同等の操作感」は再現しても、見た目は独自デザインとする
  • ゲームシステム(ルール)自体は原則保護されないが、意匠・不正競争防止法の観点も精査

本社機能の豪州→日本移転の調査

  • 前提整理:FSLの事業・資産を承継するのか(買収/事業譲渡)、無関係な新法人を日本に設立するのかで論点が全く異なる
  • 倒産時の資産(コード・DB・IP)取得可能性、清算手続きへの参加方法
  • 日本法人設立形態(株式会社/合同会社/DAO的運営との併用)と税務

その他の継続タスク

  • 利用規約・プライバシーポリシー(GPS=位置情報の個人情報保護法対応)
  • 景品表示法(報酬設計が「景品」に当たらないかの確認)
  • App Store / Google Play の暗号資産関連ガイドライン適合性
チーム詳細 ①10

管理チーム — 統制・意思決定・安全管理

ミッション

4チームを効率的かつ安全に統制する。優先順位の決定、リソース配分、対外コミュニケーションを一元管理する。

活動内容

  • 週次同期会の主催、ロードマップとバックログの管理
  • 予算管理(開発費・サーバー費・弁護士費用)と資金調達方針の決定
  • コミュニティへの進捗発信(透明性がプロジェクトの信用そのもの)
  • Xデー発生時の緊急対応指揮(移行案内の発出)

セキュリティ統制

  • リポジトリ・インフラのアクセス権限を最小権限で管理
  • 秘密鍵・APIキーの管理規程(個人保有の禁止、多署名化)
  • メンバーのオンボーディング/オフボーディング手続き
  • リサーチ活動が本家の利用規約・不正アクセス禁止法に抵触しないよう法務チームと連携して監督
成果物: プロジェクト憲章、意思決定ログ、月次予算レポート、緊急対応マニュアル
チーム間連携11

共有基盤

定例リズム

エスカレーション
